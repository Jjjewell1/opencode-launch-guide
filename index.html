opencodeAn AI-powered coding assistant that runs in your terminal. You describe what you want, and it writes the code for you. is your AI coding partner. You tell it what you want in plain English, and it writes the HTML, CSS, and JavaScript for you.

Terminal

Install opencode

INSTALL 
# macOS / Linux
curl -fsSL https://opencode.ai/install.sh | sh

# Windows (PowerShell)
iwr -useb https://opencode.ai/install.ps1 | iex

Create your project & launch

TERMINAL 
mkdir my-new-site && cd my-new-site
opencode

Describe your site

Once opencode starts, just tell it what you want:

YOUR PROMPT 
Build me a single-page portfolio site with a hero section,
an about section, a projects grid, and a contact form.
Use a dark theme with teal accents. Keep it to one HTML file.
Desktop App

Using the opencode Desktop App

  1. Download opencode from opencode.ai
  2. Install and open the application
  3. Create a new project folder and open it in the app
  4. Use the chat panel to describe your site — same prompts work here!
  5. The app shows your files updating in real time as opencode writes them

💡 Pro Tip

The desktop app gives you a visual file tree and live preview. Great if you're not comfortable with the terminal yet!

🏝️ What Just Happened?

opencode analyzed your description and generated all the files your site needs — HTML structure, CSS styling, and any JavaScript interactivity. Think of it as having a web developer who works instantly and never gets tired.

💡 Pro Tip

You can iterate conversationally. Say things like "make the header sticky" or "add a footer with social links" and opencode will update the code in place.

🔧 Troubleshooting

❌ "opencode: command not found"
Your terminal doesn't know where opencode is. Close and reopen your terminal, or restart your computer. If it still doesn't work, re-run the install command.
❌ opencode creates too many files or the wrong structure
Be more specific in your prompt. Say "keep everything in a single index.html file" to prevent it from splitting things up.

Now that your site exists on your computer, you need to put it on GitHubA website that stores your code online. Think of it as Google Drive, but specifically for code. Coolify pulls from here. so Coolify can access it.

Terminal

Step 1: Initialize the repo

TERMINAL 
git init
git add .
git commit -m "Initial site build"

Step 2: Create the GitHub repo & push

Option A — GitHub CLI (fastest):

TERMINAL 
# Install GitHub CLI first: gh.github.com
gh repo create my-new-site --public --source=. --push

Option B — Manual setup:

TERMINAL 
# After creating the repo on github.com:
git remote add origin https://github.com/YOUR_USERNAME/my-new-site.git
git branch -M main
git push -u origin main
GitHub.com Web Interface

Step 1: Create the repo on GitHub

  1. Go to github.com/new
  2. Enter a name for your repo (e.g., my-new-site)
  3. Choose Public or Private
  4. Do NOT check "Add a README file" — keep it empty
  5. Click Create repository

Step 2: Upload your files

  1. On your new repo page, click "uploading an existing file"
  2. Drag and drop your index.html (and any other files) into the upload area
  3. Click Commit changes

💡 Pro Tip

The drag-and-drop method works great for simple static sites. For ongoing development, the terminal method (Option A) is faster since you don't have to open the browser each time.

Via opencode

Let opencode handle it

Simply tell opencode:

YOUR PROMPT 
Push this project to GitHub. Create a new public repo called my-new-site.

opencode will run the git commands for you. It will ask you to confirm before pushing.

💡 Pro Tip

You'll need the GitHub CLIA command-line tool from GitHub. Install it at gh.github.com. Lets you create repos, manage PRs, and more — all from the terminal. installed for this to work. Run gh auth login first to connect your account.

🏝️ What Just Happened?

Your code now lives in two places: on your computer and on GitHub's servers. GitHub is your code's home base — Coolify will read from here, and if your computer explodes, your code is safe.

🔧 Troubleshooting

❌ "Permission denied (publickey)"
SSH isn't set up. Either configure SSH keys, or use the HTTPS URL instead: git remote add origin https://github.com/USER/REPO.git
❌ "remote: Repository not found"
Double-check the repo URL. Make sure you've already created the repo on GitHub before pushing.

CoolifyA self-hosted platform (like Heroku, but free and on your own server). It pulls your code from GitHub, builds it, and keeps it running 24/7. is where your site comes alive. It's like a personal Heroku that runs on your own hardware — it pulls code from GitHub, builds it, and keeps it running around the clock.

Coolify Dashboard

Step 1: Create a new application

  1. Open your Coolify dashboard (usually at http://YOUR_SERVER_IP:8000)
  2. Navigate to your Project (create one if you don't have one)
  3. Click + New Resource and select Application
  4. Choose GitHub as the source
  5. If prompted, authorize Coolify to access your GitHub account
  6. Select the repository and branch (main) you just pushed

Step 2: Configure the build

  1. Set the Build Pack to Static (for plain HTML/CSS/JS sites)
  2. Set Publish Directory to / (if your index.html is in the root)
  3. The internal port is usually 80 for static sites — leave the default

Step 3: Deploy

Click Deploy. Watch the build logs in real time as Coolify pulls your code, builds the container, and starts serving it.

Terminal (Advanced)

Coolify is primarily managed through its web dashboard. However, if you need to automate deployments or manage things programmatically, Coolify exposes an APIApplication Programming Interface — a way for software to talk to other software. Coolify's API lets you trigger deploys and manage apps from scripts.:

TERMINAL 
# Trigger a redeploy via Coolify's API
curl -X POST "http://YOUR_COOLIFY_URL/api/v1/applications/YOUR_APP_ID/deploy" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"

💡 Pro Tip

Find your API key in Coolify dashboard → Settings → API Tokens. The app ID is in the URL when you have an application selected.

🏝️ What Just Happened?

Coolify pulled your code from GitHub, put it inside a lightweight container (like a mini virtual machine), and started serving it on your server. Your site is now running 24/7 — you can access it via your server's internal IP address.

Step 4: Set up auto-deploy (webhook)

This is the magic step. After this, every time you push code to GitHub, Coolify automatically redeploys — no clicking required.

  1. In Coolify, go to your app → Webhooks tab → copy the webhook URL
  2. In GitHub, go to your repo → Settings → Webhooks → Add webhook
  3. Paste the Coolify URL and click Add webhook

🎉 You're Done with Coolify!

From now on, every git push (or telling opencode to "push to GitHub") triggers a zero-downtime redeploy. Your site updates itself.

🔧 Troubleshooting

❌ "Coolify can't connect to my GitHub repo"
Go to Coolify → Settings → GitHub and re-authorize. Make sure the repo isn't private unless Coolify has permission to access it.
❌ Build fails with "no such file: index.html"
Check your Publish Directory. If index.html is in the root, set it to /. If it's in a subfolder like dist/, set it to /dist.
❌ Site shows "502 Bad Gateway"
The container crashed. Check the Logs tab in Coolify for errors. Usually it's a port mismatch — make sure the port in Coolify matches what the container is actually listening on.

Your site is running on your server, but only accessible via its IP address. Cloudflare TunnelsA secure connection between your server and Cloudflare's network. It lets visitors reach your site through Cloudflare's CDN without opening ports on your firewall. connect your site to the outside world — giving you a real domain name, free HTTPS (the padlock icon), and DDoSDistributed Denial of Service — when bots flood your site with traffic to knock it offline. Cloudflare absorbs these attacks before they reach you. protection.

Cloudflare Zero Trust Dashboard

Step 1: Install cloudflared on your server

You still need one terminal command to install the connector on your server:

SSH INTO YOUR SERVER 
# Debian / Ubuntu
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared

Step 2: Create the tunnel in the dashboard

  1. Go to Cloudflare Zero Trust → Networks → Tunnels
  2. Click Create a tunnel
  3. Select Cloudflared → click Next
  4. Name your tunnel (e.g., my-site-tunnel) → click Next
  5. Cloudflare will show you an install command with a token — copy it and run it on your server

Step 3: Add a hostname

  1. Back in the dashboard, go to the Public Hostname tab
  2. Click Add a public hostname
  3. Subdomain: www (or whatever you want)
  4. Domain: select your domain from the dropdown
  5. Service Type: HTTP
  6. URL: localhost:80 (or whatever port Coolify is serving on)
  7. Click Save hostname

Step 4: Start the tunnel

Run the install command Cloudflare gave you. This starts the tunnel and connects your site to the internet:

SERVER 
# The command from the dashboard will look like this:
sudo cloudflared service install eyJhIjoiNjQ...your-token...ZHAifQ

# It automatically starts as a service — it'll survive reboots!

💡 Pro Tip

The dashboard method is great because it handles the tunnel config file for you. You don't need to manually edit config.yml — the dashboard does it all.

Terminal (Full Control)

Step 1: Install cloudflared

SERVER 
# Debian / Ubuntu
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared

Step 2: Authenticate & create tunnel

SERVER 
# Log in (opens a browser — paste the URL if SSHing remotely)
cloudflared tunnel login

# Create a named tunnel
cloudflared tunnel create my-site-tunnel

# Route your domain to the tunnel
cloudflared tunnel route dns my-site-tunnel www.yourdomain.com

Step 3: Configure the tunnel

Create or edit ~/.cloudflared/config.yml:

config.yml 
tunnel: YOUR_TUNNEL_ID
credentials-file: /root/.cloudflared/YOUR_TUNNEL_ID.json

ingress:
  - hostname: www.yourdomain.com
    service: http://localhost:80
  - service: http_status:404

Step 4: Run the tunnel

SERVER 
# Test it first (foreground)
cloudflared tunnel run my-site-tunnel

# Then install as a system service (survives reboots)
sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared

🏝️ What Just Happened?

Cloudflare is now sitting between your server and the internet. When someone visits https://www.yourdomain.com, Cloudflare routes their request through the encrypted tunnel to your Coolify server, and your site loads. The visitor has no idea where your server actually is — that's the beauty of tunnels.

🎉 Aloha, You're Live!

Visit https://www.yourdomain.com. Your site is now served through Cloudflare with automatic HTTPS, global CDN caching, and DDoS protection. 🌴

🔧 Troubleshooting

❌ "502 Bad Gateway" when visiting the domain
The tunnel can't reach your server. Check: (1) Coolify is actually serving on port 80, (2) localhost:80 in the tunnel config matches reality, (3) no firewall is blocking local connections.
❌ Tunnel connects but shows a Cloudflare error page
Your domain's DNS isn't pointing to Cloudflare. Go to your domain registrar and change the nameservers to the ones Cloudflare gave you. This can take up to 24 hours to propagate.
❌ "cloudflared: command not found"
Either the install failed or cloudflared isn't in your PATH. Try running /usr/local/bin/cloudflared --version or reinstall.
